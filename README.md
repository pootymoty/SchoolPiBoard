# SchoolPiBoard

> **Полная карта репозитория, git-workflow, CI/CD и развёртывание** —
> в [`AGENTS.md`](AGENTS.md). Читать в первую очередь, если нужно понять,
> как всё устроено и связано, или дать инструкции по обновлению сервера.

Три самостоятельных продукта в одном репозитории. Общего кода у них нет
намеренно: разные аудитории, разные домены, разные базы, разные учётные
записи. Роднит их только тема и автор. Полная карта связей и команды
развёртывания — в [`AGENTS.md`](AGENTS.md), здесь только обзор.

| Папка | Продукт | Домен | Место на сервере |
|---|---|---|---|
| `offline/` | Десктопное приложение-доска «Доска Пи» для Windows, лицензионные ключи | страница продукта | `/var/www/schoolpiboardoff` |
| `online/` | Сайт с онлайн-доской для совместной работы | school-pi-board.online | `/var/www/schoolpiboardon` |
| `main-site/` | Сервис тарифов ИИ-функций основного сайта (сам сайт — отдельный репозиторий) | нет своего, за Flask-сайтом | `/var/www/schoolpitariffs` |

## `offline/` — десктопная доска

WPF-приложение (.NET 8) для рисования на доске, полностью офлайн.
Продаётся по бессрочному ключу за разовый платёж.

| Папка | Что там |
|---|---|
| `offline/` | само приложение (`SchoolPiBoard.csproj`) |
| `offline/installer/` | установщик Inno Setup |
| `offline/server/` | сервер лицензий: ключи, устройства, пробный период, приём оплаты |
| `offline/web/` | страница покупки и скачивания |
| `offline/docs/` | развёртывание сервера ключей, платежи, оферта |

Описание продукта, сборка всех четырёх частей, порядок выпуска и история
версий — в `offline/README.md`. Пошаговый запуск с нуля —
в `offline/docs/runbook.md`.

## `online/` — онлайн-доска

Сайт с совместной работой на доске в браузере, по подписке.

| Папка | Что там |
|---|---|
| `online/server/` | ASP.NET Core + PostgreSQL + Redis: учётные записи, подписки, доски, приглашения, SignalR |
| `online/webapp/` | React + TypeScript: сайт целиком |
| `online/docs/` | развёртывание сайта, автопродление подписки |

Подробности — в `online/README.md`, пошаговый запуск —
в `online/docs/deploy.md`.

## `main-site/` — тарифы ИИ-функций основного сайта

Маленький платёжный компаньон для основного сайта `school-pi.online`
(Flask, отдельный репозиторий). Сам сайт сюда не входит — только сервис,
который ведёт подписки на тарифы и обращается за оплатой к серверу
лицензий (третий, отдельный магазин Робокассы).

| Папка | Что там |
|---|---|
| `main-site/server/SchoolPi.Tariffs/` | ASP.NET Core + PostgreSQL: подписки, автопродление |
| `main-site/docs/deploy.md` | развёртывание, настройка третьего магазина Робокассы, заявка на рекуррентные платежи |

## Что где собирается

| Что | Где собирается | Почему так |
|---|---|---|
| Приложение «Доска Пи» (`DoskaPi.exe`) | **только на ПК с Windows** | это WPF |
| Установщик `DoskaPiSetup.exe` | **только на ПК с Windows** | Inno Setup — программа для Windows |
| Сервер ключей (offline) | на ПК, на сервере или в CI (публикует релиз) | обычное приложение .NET |
| Сервис тарифов (main-site) | на ПК, на сервере или в CI (публикует релиз) | то же самое |
| Сервер онлайн-доски | на ПК или на сервере — **CI для него не заведён** | то же самое, но без автосборки |
| Веб-приложение онлайн-доски | на ПК или на сервере — **CI для него не заведён** | нужен Node.js |
| Страницы покупки и оферты (offline) | собирать не надо | готовые HTML-файлы |

Сервер, на котором всё работает, слабый, поэтому на нём ничего не собирается:
сервер ключей и сервис тарифов приезжают готовым архивом из GitHub Actions,
остальное собирается на ПК и доставляется вручную.

**На ПК с Windows:** .NET 8 SDK, Inno Setup 6 (для установщика), Node.js 20+
(для сайта), Git.

**На сервере:** ASP.NET Core Runtime 8 (именно runtime, SDK не нужен),
PostgreSQL, Redis (только для онлайн-доски), nginx и сертификаты Let's Encrypt.

## Почему это не один проект

Первым появилось десктопное приложение с ключами, вторым — сайт с подпиской,
третьим — тарифы основного сайта. Соблазн переиспользовать «уже написанный
сервер» был каждый раз, но это связало бы разные продукты общей базой и
общими учётными записями: покупатель коробки, подписчик доски и подписчик
тарифов — разные люди с разными сценариями. Разделение проведено по папкам
и доведено до конца — код одного продукта не зависит от кода другого.
Единственное намеренное исключение — сервер лицензий обслуживает все три
магазина Робокассы (лицензии, подписка доски, тарифы) одним и тем же
процессом, но их настройки и данные внутри него не пересекаются (см.
`AGENTS.md`, раздел 4).
