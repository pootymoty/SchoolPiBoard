# SchoolPiBoard — десктопная доска

Приложение для рисования на доске под Windows: работает полностью офлайн,
доски хранятся на компьютере пользователя. Продаётся по бессрочному ключу
за разовый платёж, до покупки доступны три бесплатных дня.

Требования: Windows 10 или 11, 64-разрядная. Ничего доустанавливать не нужно —
рантайм .NET входит в установщик.

Этот файл — единственная документация десктопного продукта: и описание,
и настройка всех его частей, и порядок выпуска.

## Как всё связано

```
Покупатель на странице покупки (web/)
        │  вводит почту, нажимает «Перейти к оплате»
        ▼
Сервер ключей (server/)  ──► Робокасса ──► покупатель платит
        │                         │
        │  ◄── уведомление об оплате (ResultURL)
        ▼
Выпускает ключ, отправляет письмом
        │
        ▼
Покупатель ставит приложение (installer/) и вводит ключ
        │
        ▼
Приложение (корень) ──► сервер ключей: «этот ключ мой?»
                        привязка к компьютеру, максимум 2 штуки
```

Отсюда главное правило: **приложение должно знать адрес сервера ключей**,
и адрес этот зашивается в exe при сборке. Поэтому сервер настраивается
раньше, чем собирается установщик.

## Что настраивается

Всё лицензирование настраивается в одном месте — `LicenseState.cs`,
класс `LicenseOptions`:

```csharp
// Адрес сервера ключей. Зашивается в exe при сборке.
public const string DefaultServerUrl = "https://keys.school-pi.online";

// Сколько компьютеров на один ключ (окончательное слово за сервером).
public const int DefaultDeviceLimit = 2;

// Длительность пробного периода (срок назначает сервер).
public const int TrialDays = 3;

// Не чаще раза в сутки — фоновый вопрос «не отозван ли ключ».
// Ничего не требует и ничего не блокирует при отсутствии связи.
public static readonly TimeSpan ValidationInterval = TimeSpan.FromDays(1);
```

Периодической обязательной проверки нет: купленный ключ бессрочный,
приложение офлайновое, и требовать выхода в сеть «раз в N дней» не за что.
Единственное, что делает фоновая проверка, — узнаёт об отозванном ключе,
и только тогда, когда интернет и так есть.

Версия продукта — в `SchoolPiBoard.csproj`:

```xml
<Version>2.2.1</Version>
```

Текст соглашения внутри приложения — `Eula.cs`. Он показывается
в «О программе»; более полный текст лежит в `installer/LICENSE.txt`,
менять их стоит вместе.

## Как собрать и проверить

Нужен **.NET 8 SDK**.

```
cd offline
build.bat
```

Результат — `offline\publish\SchoolPiBoard.exe`. Запускается прямо оттуда,
установщик для проверки не нужен.

Если сервер ключей ещё не поднят, а посмотреть приложение хочется, укажите
временный адрес переменной окружения — пересобирать не придётся:

```
set SCHOOLPIBOARD_LICENSE_URL=http://localhost:5000
publish\SchoolPiBoard.exe
```

## Где приложение хранит данные

| Что | Где |
|---|---|
| доски | `%APPDATA%\SchoolPiBoard\boards.json` |
| настройки | `%APPDATA%\SchoolPiBoard\settings.json` |
| лицензия | `%APPDATA%\SchoolPiBoard\license.dat` (зашифрован) |
| метка пробного периода | `HKCU\Software\SchoolPiBoard` и `%ProgramData%\SchoolPiBoard` |
| журнал ошибок | `%APPDATA%\SchoolPiBoard\crash.log` |

`settings.json` можно править вручную — например, задать другой адрес
сервера, не пересобирая приложение:

```json
{
  "DataFolder": "C:\\Users\\Имя\\AppData\\Roaming\\SchoolPiBoard",
  "LicenseServerUrl": "https://keys.school-pi.online"
}
```

Приоритет такой: переменная окружения `SCHOOLPIBOARD_LICENSE_URL` →
`LicenseServerUrl` из `settings.json` → зашитое значение.

## Как сбросить состояние при проверке

Чтобы приложение снова показало экран активации:

```
del "%APPDATA%\SchoolPiBoard\license.dat"
```

Чтобы снова стал доступен пробный период (он даётся один раз на компьютер),
этого мало — метки лежат отдельно:

```
reg delete "HKCU\Software\SchoolPiBoard" /f
rmdir /s /q "%ProgramData%\SchoolPiBoard"
```

И даже это не поможет: сервер помнит выданный пробный период по отпечатку
компьютера. Полный сброс — удалить строку из таблицы `trial_activations`
(см. часть 3).

#define AppName "SchoolPiBoard"

| Строка | Что делает |

## Как собрать

Нужны **.NET 8 SDK** и **Inno Setup 6** (https://jrsoftware.org/isdl.php).

Способ первый:

```
cd offline

```

Способ второй, без командной строки: сначала `build.bat` (соберёт

## Что увидит пользователь

Приветствие → соглашение → пояснения → выбор папки → выбор папки
в меню Пуск → галочка «ярлык на рабочем столе» → установка → последняя
страница с галочкой «Запустить SchoolPiBoard и ввести ключ регистрации».

Если галочку снять — ключ спросится при первом запуске. Оба сценария
рабочие, приложение без ключа просто не пускает дальше экрана активации.

## Что установщик намеренно не удаляет

При удалении программы остаются:

- `%APPDATA%\SchoolPiBoard` — доски и настройки пользователя;
- `HKCU\Software\SchoolPiBoard` и `%ProgramData%\SchoolPiBoard` — метки
  пробного периода.

Первое — чтобы переустановка не стирала работу. Второе — чтобы «удалить
и поставить заново» не превращалось в новые три бесплатных дня.

## Подпись

Установщик не подписан, и Windows покажет предупреждение SmartScreen.
Подробности — ниже, в разделе «Подпись установщика».

---

### Решения, принятые в скрипте

**Приложение публикуется self-contained.** Рантайм .NET лежит внутри
исполняемого файла, поэтому установщику нечего докачивать: он работает
на чистой Windows 10/11 и без интернета. Цена — около 200 МБ размера.

Если когда-нибудь понадобится обратный вариант (маленький установщик, который
докачивает .NET 8 Desktop Runtime), меняется два места: в `SchoolPiBoard.csproj`
убирается `SelfContained`, а в `[Code]` скрипта добавляется проверка наличия
рантайма (ключ реестра `HKLM\SOFTWARE\WOW6432Node\dotnet\Setup\InstalledVersions\x64\sharedfx\Microsoft.WindowsDesktop.App`)
и загрузка установщика рантайма. Пока такой сценарий не нужен, кода в скрипте нет.

**Установка не требует прав администратора.** `PrivilegesRequired=lowest`
плюс диалог выбора: «для всех пользователей» (нужен администратор) или
«только для меня». Учитель на школьном компьютере без админских прав
поставит программу себе.

**Последняя страница мастера** предлагает запустить программу с ключом
регистрации (`SchoolPiBoard.exe --activate`). Галочку можно снять — тогда ключ
спросится при первом запуске. Оба сценария из технического задания
(«ввести сразу» и «ввести позже») это и есть.

**Деинсталлятор не трогает три вещи:**

- `%APPDATA%\SchoolPiBoard` — доски и настройки пользователя;
- `HKCU\Software\SchoolPiBoard` и `%ProgramData%\SchoolPiBoard` — метки
  пробного периода. Иначе «удалить и поставить заново» давало бы новые
  три дня бесплатно.

Это осознанное поведение, а не забытая уборка.

### Подпись установщика

Установщик сейчас **не подписан**. При первом запуске Windows покажет синее
окно SmartScreen «Windows защитила ваш компьютер» с кнопкой «Подробнее →
Выполнить в любом случае». Программа запустится, но выглядит это тревожно,
и часть покупателей на этом останавливается.

Убирается это только сертификатом для подписи кода (code signing):

- **OV-сертификат** — дешевле, но репутация у SmartScreen набирается
  постепенно, первые недели предупреждение может оставаться;
- **EV-сертификат** — дороже и требует аппаратный ключ, зато доверие
  выдаётся сразу.

Когда сертификат появится, подпись добавляется в `SchoolPiBoard.iss` парой
строк (`SignTool`), пересборка — обычная. До тех пор имеет смысл написать
на странице скачивания, что предупреждение ожидаемо.

### Проверка перед выпуском

1. Поставить на чистую виртуальную машину с Windows 10/11 без .NET —
   программа должна запуститься.
2. Пройти установку «только для меня» на пользователе без прав администратора.
3. На последней странице оставить галочку — должен открыться экран ввода ключа.
4. Удалить программу и поставить заново — пробный период не должен начаться
   заново, а доски должны остаться на месте.

# Часть 3. Сервер ключей (`server/`)

## Что он делает

- принимает оплату (уведомление от Робокассы), выпускает ключ,
  отправляет письмо;
- активирует ключ на компьютере, следит за лимитом в два устройства;
- отвечает приложению на фоновую проверку раз в сутки;
- выдаёт пробный период и помнит, что этот компьютер его уже брал;
- освобождает слот устройства при переезде на другой компьютер.

## Что за файлы

| Файл | Отвечает за |
|---|---|
| `Program.cs` | запуск, настройки, ограничение частоты, маршруты |
| `Configuration/ServerOptions.cs` | **все настройки и их проверка при старте** |
| `Data/*.cs` | таблицы: лицензии, активации, пробные периоды, платежи |
| `Data/DatabaseInitializer.cs` | применение схемы при старте |
| `sql/001_init.sql`, `sql/002_*.sql` | сама схема |

| `Endpoints/TrialEndpoints.cs` | пробный период |
| `Endpoints/PurchaseEndpoints.cs` | выставление счёта и приём оплаты |

| `Services/TrialService.cs` | выдача пробного периода |

| `Services/TokenService.cs` | подписанный токен активации |

## Настройки

Читаются в `Configuration/ServerOptions.cs`. Секреты — только через
переменные окружения, в `appsettings.json` лежат пустые заглушки.

| Переменная | Обязательна | Что это |
|---|---|---|
| `ConnectionStrings__Postgres` | да | подключение к базе |
| `LICENSE_TOKEN_SECRET` | да | секрет подписи токенов активации |
| `Smtp__Host`, `Smtp__FromEmail` | в Production | почта, с которой уходит письмо с ключом |
| `Smtp__User`, `SMTP_PASSWORD` | в Production | вход в почтовый ящик |
| `Smtp__Port`, `Smtp__UseStartTls` | нет | 465 + SSL по умолчанию; 587 + STARTTLS — второй вариант |
| `Robokassa__MerchantLogin` | для продаж | логин магазина |
| `ROBOKASSA_PASSWORD1` | для продаж | подпись ссылки на оплату |
| `ROBOKASSA_PASSWORD2` | для продаж | проверка уведомления об оплате |
| `Robokassa__Amount` | нет | цена, по умолчанию 2999.00 |
| `Robokassa__IsTest` | нет | тестовый режим (`true`/`false`, не `1`) |
| `License__DeviceLimit` | нет | устройств на ключ, по умолчанию 2 |
| `License__DownloadUrl` | нет | ссылка на установщик в письме |
| `License__SupportEmail` | нет | адрес поддержки в письме |
| `Trial__Days` | нет | пробный период, по умолчанию 3 |
| `Web__SiteUrl` | нет | адрес страницы покупки |

### Почта

Письма уходят обычным SMTP — Яндекс 360, ящик `info@school-pi.online`.
В `SMTP_PASSWORD` кладётся **пароль приложения** из Яндекс ID, а не пароль
от почты: обычный пароль SMTP не примет.

Порт по умолчанию 465 с SSL. Если он закрыт на сервере, второй рабочий
вариант — `Smtp__Port=587` и `Smtp__UseStartTls=true`.

Пока SMTP не настроен, сервис поднимается только в режиме разработки:
ключ выпускается, а письмо целиком пишется в лог — этого достаточно,
чтобы проверить весь путь покупки, не отправляя писем.

## Эксплуатация

Выпустить ключ вручную, без оплаты (PostgreSQL 13+):

```sql
INSERT INTO licenses (id, key, email, created_at, revoked)
VALUES (gen_random_uuid(), 'ABCD-EFGH-JKMN-PQRS', 'user@mail.ru', now(), false);
```

В ключе только символы `ABCDEFGHJKMNPQRSTUVWXYZ23456789` — без `I`, `L`,
`O`, `0` и `1`, чтобы ключ можно было продиктовать по телефону.

Отозвать ключ (приложение заблокируется при следующей фоновой проверке):

```sql
UPDATE licenses SET revoked = true WHERE key = 'ABCD-EFGH-JKMN-PQRS';
```

Освободить слот устройства (человек сменил компьютер и не отвязал старый):

```sql
DELETE FROM license_activations
 WHERE license_id = (SELECT id FROM licenses WHERE key = 'ABCD-EFGH-JKMN-PQRS');
```

Посмотреть, кто брал пробный период:

```sql
SELECT email, started_at, expires_at FROM trial_activations ORDER BY started_at DESC LIMIT 20;
```

Выдать пробный период повторно:

```sql
DELETE FROM trial_activations WHERE email = 'user@mail.ru';
```

Посмотреть оплаты:

```sql
SELECT invoice_id, email, amount, status, created_at, paid_at
  FROM payments ORDER BY created_at DESC LIMIT 20;
```

### Модель лицензии

- Разовая оплата → один перманентный ключ формата `XXXX-XXXX-XXXX-XXXX`, без срока действия.
- Ключ живёт максимум на **2 устройствах** одновременно (значение настраивается: `License:DeviceLimit`).
- Интернет нужен только для активации ключа. Дальше приложение работает
  офлайн неограниченное время: ничего не требует и ничем не грозит.
- Когда связь есть, приложение не чаще раза в сутки молча спрашивает сервер,
  не отозван ли ключ. Нет связи — нет и вопроса, работа продолжается.
- До покупки — **пробный период 3 дня**, один раз на компьютер. Решение о выдаче
  принимает сервер: локальные метки на компьютере стираются переустановкой,
  запись в базе — нет.

### Эндпоинты

#### `POST /license/activate`

```json
{ "key": "ABCD-EFGH-JKMN-PQRS", "hardwareId": "8F2C…" }
```

| Ответ | Когда |
|---|---|
| `200 { token, key, email, activatedAt, devicesUsed, deviceLimit }` | слот занят этим устройством (в том числе повторно) |
| `400 { error: "bad_request" }` | ключ не той длины/формата |
| `403 { error: "invalid_key" }` | ключа нет или он отозван |
| `409 { error: "device_limit", devicesUsed, deviceLimit }` | все слоты заняты другими устройствами |

`token` — JWT (HS256) без даты истечения, с полем `issuedAt`. Клиент хранит его
как есть и не разбирает; подпись проверяет сервер.

Проверка лимита выполняется в транзакции с `SELECT … FOR UPDATE` по строке
лицензии — два одновременных запроса не смогут занять третий слот.

#### `POST /license/validate`

Тело то же. Всегда `200`:

```json
{ "valid": true, "reason": "ok", "devicesUsed": 1, "deviceLimit": 2 }
```

Отдельный код ошибки здесь был бы вреден: клиенту важно отличать «сервер сказал
нет» (блокировать приложение) от «до сервера не достучались» (продолжать работу).

#### `POST /license/deactivate`

Освобождает слот устройства — нужно при переезде на новый компьютер.
`200 { ok: true }`, если слот освобождён или его уже не было.


#### `POST /trial/start`

```json
{ "hardwareId": "8F2C…", "email": "user@example.com" }
```

| Ответ | Когда |
|---|---|
| `200 { status: "started", startedAt, expiresAt, days }` | период выдан впервые |
| `200 { status: "resumed", … }` | период уже шёл — отдаём остаток, а не новые дни |
| `409 { error: "trial_used", expiresAt }` | этот компьютер (или эта почта) период уже использовал |
| `400 { error: "bad_request" }` | почта или идентификатор устройства не приняты |

Переустановка приложения посреди пробного периода не начинает отсчёт заново:
сервер возвращает ту же дату окончания.

#### `POST /purchase/start`

Принимает и обычную форму (`email=…`), и JSON (`{ "email": "…" }`).

- Форме отвечает `302` на страницу оплаты Робокассы — поэтому странице сайта
  не нужен ни JavaScript, ни CORS.
- JSON-запросу отвечает `200 { paymentUrl, invoiceId, amount }`.
- Если Робокасса не настроена — `503`.

#### `POST|GET /payment/robokassa/result`

ResultURL Робокассы. Проверяет подпись на Password2, выпускает ключ,
отправляет письмо и отвечает строкой `OK{InvId}` — иначе Робокасса
считает уведомление недоставленным и повторяет его.

Повторное уведомление о том же счёте лицензию не дублирует.

#### `GET /health`

`200 { "status": "ok" }`.

### Ограничение частоты

Fixed window по IP-адресу: `/license/activate`, `/license/deactivate`,
`/trial/start` и `/purchase/start` — 10 запросов в минуту,
`/license/validate` — 60. Превышение → `429`.

За обратным прокси включите `UseForwardedHeaders` с указанием доверенных
адресов (`KnownProxies`/`KnownNetworks`), иначе все клиенты будут выглядеть
как один IP прокси и делить общий лимит.

### Настройка Робокассы

В личном кабинете магазина:

1. **ResultURL** — `https://ваш-домен/payment/robokassa/result`, метод POST.
   Именно по нему сервис узнаёт об оплате; браузеру покупателя в этом
   вопросе не верим вовсе.
2. **SuccessURL** и **FailURL** — страницы вашего сайта («спасибо, ключ
   отправлен на почту» и «оплата не прошла»). Сервер лицензий в них не участвует.
3. Пароли №1 и №2 — в переменные `ROBOKASSA_PASSWORD1` и `ROBOKASSA_PASSWORD2`.
4. Пока идёт проверка — `Robokassa__IsTest=true`: деньги не списываются,
   а весь путь до выдачи ключа работает по-настоящему.

**Третий пароль (для JWT) сервису не нужен.** Он относится к отдельному
JWT-API Робокассы, а мы работаем по классическому протоколу
`Merchant/Index.aspx` с подписью MD5. Класть его в `LICENSE_TOKEN_SECRET`
нельзя: это наш собственный секрет подписи токенов активации, он никак
не связан с Робокассой и генерируется случайно (`openssl rand -hex 32`).

**Метод запроса.** ResultURL должен быть POST — наш обработчик принимает
и POST, и GET, так что здесь проблем не будет. А вот SuccessURL и FailURL
с методом POST ведут на **ваш сайт**: если это Flask, маршрут должен
принимать POST (`methods=["GET", "POST"]`), иначе покупатель после оплаты
увидит 405. Проще выставить для них GET.

#### Тестовый режим

При `Robokassa__IsTest=true` подпись считается **тестовой** парой паролей,
при `false` — боевой. Это разные пароли: переключая режим, меняйте и их,
иначе Робокасса ответит «неверная подпись».

### Про чек

`Robokassa__SendReceipt` по умолчанию **выключен**. Для самозанятого чек, как
правило, формирует сама Робокасса, и передавать состав чека параметром
`Receipt` не требуется. Включайте флаг только если в кабинете включена
фискализация с составом чека — тогда состав берётся из `Robokassa:Description`,
`Amount`, `TaxSystem` (`npd`), `Tax` (`none`) и `PaymentObject`.

`Robokassa__PaymentObject` по умолчанию `intellectual_activity` —
«предоставление прав на результаты интеллектуальной деятельности».
Это соответствует предмету оферты: продаётся лицензия, а не услуга.

Важная деталь на случай отладки: в подпись ссылки на оплату входит **уже
закодированная** строка `Receipt`, ровно в том виде, в каком она уходит
в адресе. Это самое частое место ошибки при интеграции — если Робокасса
отвечает «неверная подпись» с включённым чеком, смотреть надо сюда
(`RobokassaService.BuildPaymentUrl`).

### Проверка связки с клиентом

Адрес сервера в десктопном приложении берётся из переменной окружения
`SCHOOLPIBOARD_LICENSE_URL` (перекрывает всё), иначе из `LicenseServerUrl`
в `%APPDATA%\SchoolPiBoard\settings.json`.

```powershell
$env:SCHOOLPIBOARD_LICENSE_URL = "http://localhost:5000"
.\SchoolPiBoard.exe
```

### Чего здесь намеренно нет

- Личного кабинета и админки: отозвать ключ и освободить слот проще запросом в базу.
- Очереди писем: одно письмо на оплату, синхронной отправки достаточно —
  при сбое Робокасса повторит уведомление, и письмо уйдёт со второй попытки.
- Защиты от подбора ключей с распределённого ботнета: ограничитель работает по IP.
  Перебор 16 символов из алфавита в 31 знак (~79 бит) и так не имеет смысла.

# Часть 4. Страница покупки (`web/`)

## Что это

`index.html` — одна самодостаточная страница: стили внутри, скриптов нет.
Форма покупки отправляет обычный POST на сервер ключей, тот заводит счёт
и переадресует человека на форму Робокассы. Поэтому странице не нужны
ни JavaScript, ни настройка CORS — нечему ломаться при вставке в чужую
вёрстку.

Файл безопасен для шаблонов Jinja: в нём нет последовательностей, которые
Flask принял бы за подстановку. Можно положить прямо в `templates/`.

## Что проверить

**Цена**, если изменится, — в трёх местах: кнопка в шапке, блок цены,
раздел условий. И отдельно на сервере: `Robokassa__Amount`.

**Адрес страницы оферты**, если он переедет с `/offer/schoolpiboard-desktop`, —
в блоке покупки, в блоке условий и в подвале.

Уже подставлено: адрес сервера ключей в форме, ссылка на установщик
(`/download/SchoolPiBoardSetup.exe`), почта поддержки, реквизиты продавца,
условия возврата.

## Куда положить установщик

Ссылка со страницы ведёт на `/download/SchoolPiBoardSetup.exe`. Положите файл
так, чтобы этот адрес работал, и укажите тот же адрес в переменной
`License__DownloadUrl` на сервере — он попадает в письмо с ключом.

## Оформление

Все цвета и размеры — переменные в начале блока `<style>`. Чтобы подогнать
страницу под сайт, обычно достаточно поменять их; если у сайта своя система
стилей, блок `<style>` можно удалить целиком — разметка размечена классами
(`card`, `button`, `steps`, `terms`, `faq`).

---

### Как встроить во Flask

Файл безопасен для Jinja: в нём нет ни `{`+`{`, ни `{`+`%`, ни `{`+`#`
(Jinja разбирает такие последовательности даже внутри HTML-комментариев).
Поэтому его можно положить в `templates/` как есть:

```python
@app.get("/board")
def board_page():
    return render_template("board.html")
```

Если страница статическая — она одинаково хорошо работает и из `static/`.

2. **Тестовый ключ** — вставить строку в `licenses` (часть 3 выше).

9. **Боевой режим** — `Robokassa__IsTest=false`, реальная покупка на себя.

# Частые проблемы

**Приложение говорит «нет связи с сервером».**
Проверьте `DefaultServerUrl` в собранной версии и что `/health` отвечает
снаружи. Быстрая проверка без пересборки: `set SCHOOLPIBOARD_LICENSE_URL=...`.

**Ключ не принимается, хотя он есть в базе.**
Ключ сравнивается в каноническом виде `XXXX-XXXX-XXXX-XXXX`, регистр
приводится сам. Проверьте, что в базе он записан именно так и что
`revoked = false`.

**«Ключ уже используется на 2 компьютерах».**
Так и задумано. Освободить слот: в приложении на ненужном компьютере
Настройки → «О программе и лицензии» → «Отвязать этот компьютер», либо
запросом к базе (часть 3).

**Пробный период не предлагается.**
Значит, метка уже есть — в реестре, в ProgramData или на сервере.
Полный сброс описан в части 1.

**Приложение просит интернет после активации.**
Не должно: после успешной активации подключение не требуется вовсе.
Если такое видите — это ошибка, пришлите снимок экрана.

**Русский текст в мастере установки — крякозябры.**
Файл `.iss`, `LICENSE.txt` или `BEFORE.txt` сохранён без BOM.

**Windows ругается на неизвестного издателя.**
Установщик не подписан, см. раздел «Подпись установщика».

**Сборка падает с ошибками компиляции.**
Код писался в среде без .NET SDK и ни разу не компилировался. Первая сборка
может выявить опечатки — пришлите вывод `dotnet build`, поправлю.

# История версий

## Версия 2.2.1 — редактор: штрихи, ластик, трансформация

Правки редактора, сделанные владельцем продукта отдельно от лицензионной
и серверной части. Номер версии не менялся.

**Рукописные штрихи.** Близкие последовательные штрихи пера, пера 2
и маркера объединяются в один объект: тот же инструмент и параметры,
расстояние до 25 экранных пикселей, пауза до 500 мс. Сегменты внутри
объекта остаются раздельными, поэтому соседние буквы не соединяются
линией, а Ctrl+Z отменяет последнее касание, а не всё слово целиком.

**Ластик.** Изображения не затрагивает. Фигуры, текст и стрелки удаляет
целиком. Прямая-фигура остаётся одним объектом, следы стирания пишутся
в `ErasePoints`. Рукописный штрих тоже остаётся одним объектом: после
частичного стирания внутри него хранятся оставшиеся сегменты. Пять
размеров: 8, 16, 26, 60, 120.

**Трансформация.** Ручки масштабирования и вращения есть у фигур,
изображений и текста. У обычных штрихов пера и маркера их нет.
У прямой и стрелки, а также у выпрямленного штриха — две ручки на концах:
перетаскивание одного конца оставляет второй на месте и меняет сразу
длину и угол.

**Стили линий.** Solid, Dash, DashDot, Dot — для фигур, линий-стрелок
и выпрямленных штрихов пера и маркера. Заливка скрыта у всех штрихов
пера и маркера и у линий и стрелок.

## Версия 2.2.1 — переименование в SchoolPiBoard

Продукт называется SchoolPiBoard. Переименованы название приложения
и установщика, сборка (`SchoolPiBoard.exe`), пространства имён, иконка,
папка данных, ветка реестра и переменная окружения с адресом сервера.

Что это ломает у тех, кто ставил предыдущую сборку:

| Что | Было | Стало |
|---|---|---|
| Файл установщика | `WhiteboardSetup.exe` | `SchoolPiBoardSetup.exe` |
| Папка данных | `%APPDATA%\WhiteboardApp` | `%APPDATA%\SchoolPiBoard` |
| Ветка реестра | `HKCU\Software\WhiteboardApp` | `HKCU\Software\SchoolPiBoard` |
| Переменная адреса сервера | `WHITEBOARD_LICENSE_URL` | `SCHOOLPIBOARD_LICENSE_URL` |

Доски и лицензия из старой папки автоматически не переезжают: старая
сборка ставится и удаляется отдельно от новой. Доски переносятся
копированием `boards.json` в новую папку, ключ вводится заново.

Отдельно: изменились строки-соли в `HardwareId` и `LocalCrypto`, поэтому
отпечаток компьютера стал другим. Прежние активации на сервере указывают
на несуществующие устройства и занимают слоты — их нужно удалить из
таблицы `license_activations`. Пока покупателей нет, это безболезненно;
после запуска продаж такую правку делать уже нельзя.

Что в приложении появилось на каждом шаге. Раздел справочный: он объясняет,
почему некоторые вещи сделаны именно так.

  клик считается вручную.
- **Поворот** объектов — за круглый маркер над рамкой, с Shift шаг 15°.
- **Штрихи при повороте**: точки хранятся без поворота, угол применяется при
  отрисовке — так поворот не накапливает искажения.
- **Экспорт PNG** сохраняет всё содержимое доски, а не видимую область.
- При ошибке запуска подробности пишутся в
  `%APPDATA%\SchoolPiBoard\crash.log` и показываются с первопричиной.
