# Что делает сайт school-pi.online для десктопной доски

Памятка для того, кто ведёт сайт. Коротко: сайт показывает страницы
и отправляет форму. Деньги, ключи и письма — не его работа.

## Разделение контуров

Продуктов два, и платежи у них не пересекаются нигде:

| | Десктопная доска | Онлайн-доска |
|---|---|---|
| Что продаётся | бессрочный ключ, разовый платёж | подписка |
| Домен | school-pi.online | school-pi-board.online |
| Кто принимает оплату | сервер ключей, keys.school-pi.online | сервер онлайн-доски |
| Адрес уведомления | `/payment/robokassa/result` | `/billing/robokassa/result` |
| Магазин Робокассы | свой | свой |
| База | `schoolpiboard_licenses` | `schoolpiboard_online` |
| Нумерация счетов | своя последовательность | своя последовательность |

Сайт не участвует ни в одном из контуров.

## Что сайт делает

| Путь | Что там |
|---|---|
| `/` | страница покупки и скачивания — готовый файл `offline/web/index.html` |
| `/offer/schoolpiboard-desktop` | оферта — готовый файл `offline/web/offer.html` |
| `/privacy` | политика обработки персональных данных — **ещё не написана** |
| `/download/SchoolPiBoardSetup.exe` | установщик, отдаётся статикой |
| `/success` | «спасибо, письмо с ключом придёт в течение нескольких минут» |
| `/fail` | «оплата не прошла» |

`/success` и `/fail` в кабинете Робокассы настроены на метод POST, поэтому
маршруты должны принимать POST: `methods=["GET", "POST"]`. Иначе покупатель
после оплаты увидит 405.

## Форма покупки

Единственная точка соприкосновения с платежами:

```html
<form method="post" action="https://keys.school-pi.online/purchase/start">
  <input name="email" type="email" required>
</form>
```

Обычный кросс-доменный POST формой. Сервер ключей заводит счёт и отвечает
редиректом на форму Робокассы. Ни JS, ни fetch, ни прокси через Flask
не нужны — они только ломают редирект.

## Чего сайт не делает

- **не заводит заказы.** Номер счёта выдаёт последовательность в базе
  сервера ключей, и он же приходит обратно в уведомлении от Робокассы.
  Второй источник номеров означает, что Робокасса пришлёт `InvId`,
  которого сервер ключей не знает: он ответит `unknown invoice`, а
  покупатель заплатит и останется без ключа;
- **не считает и не проверяет подписи.** Password1 и Password2 лежат
  в `/etc/schoolpiboardoff.env` в одном месте. Копия секрета в конфиге
  сайта — это второе место, откуда он может утечь, без всякой пользы;
- **не принимает уведомления об оплате.** ResultURL ведёт на сервер ключей;
- **не выдаёт ключи и не пишет в таблицу лицензий.** Приложение активирует
  только те ключи, которые сервер ключей выпустил сам;
- **не отправляет письмо с ключом.** Его отправляет сервер ключей сразу
  после проверки подписи уведомления;
- **не считает оплату состоявшейся на `/success`.** Браузер может прийти
  туда и без оплаты — это просто страница с текстом.

## Если письмо с ключом выглядит неправильно

Шаблон письма живёт в сервере ключей
(`offline/server/SchoolPiBoard.LicenseServer/Services/EmailTemplate.cs`),
а не на сайте. Правка шаблона попадает к покупателям только после
обновления сервиса — см. `runbook.md`, раздел «Обновление сервиса».
