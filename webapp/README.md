# Whiteboard — веб-приложение

React + TypeScript + Vite. Фаза 2, этап **2a**: вход, список досок, участники
и роли, подключение к комнате доски по SignalR с показом присутствующих.
Холст появится на этапе 2b.

## Запуск

```bash
cd webapp
npm install
cp .env.example .env      # при необходимости поправить адрес API
npm run dev               # http://localhost:5173
```

Порт 5173 зафиксирован намеренно: он перечислен в `Web:AppOrigins` на сервере,
иначе браузер не пустит приложение к API.

Сервер должен быть запущен отдельно (`server/Whiteboard.LicenseServer`),
по умолчанию на `http://localhost:5000`.

```bash
npm run build       # проверка типов + сборка в dist/
npm run typecheck   # только проверка типов
```

## Что где

| Путь | Что делает |
|---|---|
| `src/api/client.ts` | обёртка над fetch: токен, разбор ошибок сервера в понятный текст |
| `src/auth/AuthContext.tsx` | вход, регистрация, восстановление сессии по токену из localStorage |
| `src/realtime/useBoardHub.ts` | подключение к SignalR-хабу, присутствие, курсоры, переподключение |
| `src/pages/BoardsPage.tsx` | список досок, создание, удаление |
| `src/pages/BoardPage.tsx` | комната доски: кто в сети, панель участников, место под холст |
| `src/components/MembersPanel.tsx` | приглашение по почте, смена роли, удаление участника |

## Решения

**Права проверяются на сервере, а не здесь.** Панель участников прячет кнопки
от тех, кому они не положены, но это только удобство: сервер отклоняет чужие
действия сам. Скрытая кнопка защитой не является.

**После обрыва связи клиент не «догоняет» пропущенные события.** SignalR сам
переподключается, после чего мы заново вызываем `JoinBoard` и получаем
состояние комнаты целиком. Это заметно надёжнее, чем пытаться восстановить
порядок событий, и то же решение пригодится для холста на этапе 2b.

**Курсор отправляется не чаще 20 раз в секунду.** На каждое движение мыши
слать событие незачем: глазу разницы нет, а трафика и работы серверу — вдвое.
