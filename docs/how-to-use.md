# Как пользоваться репозиторием

Репозиторий — это **исходники**. На сервер уезжают не они, а результат
сборки: несколько собранных файлов. Ниже — что где собирается и что куда
кладётся.

```
offline/   десктопная доска: приложение, установщик, сервер лицензий, страница продукта
online/    сайт school-pi-board.online: сервер и веб-приложение
docs/      памятки: развёртывание, платежи, эта инструкция
```

---

## Что где собирается

| Что | Где собирается | Почему так |
|---|---|---|
| Приложение Whiteboard (.exe) | **только на вашем ПК с Windows** | это WPF, он собирается под Windows |
| Установщик (WhiteboardSetup.exe) | **только на вашем ПК с Windows** | Inno Setup — программа для Windows |
| Сервер лицензий | на ПК или на сервере | обычное приложение .NET, работает и там, и там |
| Сервер онлайн-доски | на ПК или на сервере | то же самое |
| Веб-приложение (сайт) | на ПК или на сервере | нужен Node.js |
| Страница покупки десктопной версии | ничего собирать не надо | это готовый HTML-файл |

Удобнее собирать всё на своём ПК и отправлять на сервер готовое: серверу
тогда не нужны ни SDK, ни Node.js, ни исходники.

---

## Что нужно поставить

**На вашем ПК (Windows):**

- .NET 8 SDK — https://dotnet.microsoft.com/download/dotnet/8.0
- Inno Setup 6 — https://jrsoftware.org/isdl.php (только для установщика)
- Node.js 20+ — https://nodejs.org (только для сайта)
- Git

**На сервере (Linux):**

- ASP.NET Core Runtime 8 (именно runtime, SDK не нужен)
- PostgreSQL — **две отдельные базы**
- Redis — только для онлайн-доски
- nginx + сертификаты Let's Encrypt

## Десктопная доска (`offline/`)

### 1. Приложение и установщик — на вашем ПК

```
git clone https://github.com/pootymoty/SchoolPiBoard
cd SchoolPiBoard\offline
```

Просто приложение, чтобы посмотреть и проверить:

```
build.bat
```

Результат: `offline\publish\Whiteboard.exe` — можно запускать прямо оттуда.

Установщик для раздачи покупателям:

```
installer\build-installer.bat
```

Результат: `offline\dist\WhiteboardSetup.exe`. **Это единственный файл,
который получает покупатель.** Его нужно положить туда, куда ведёт кнопка
«Скачать» на странице покупки.

> Перед первой сборкой установщика поправьте в `offline\installer\Whiteboard.iss`
> строку `AppPublisher` (там заглушка с ФИО) и тексты в `LICENSE.txt`.
> И в `offline\LicenseState.cs` — `DefaultServerUrl`: приложение должно знать
> настоящий адрес сервера лицензий, иначе установленные копии никуда
> не достучатся.

### 2. Сервер лицензий — на сервер

Собрать на ПК:

```
cd SchoolPiBoard\offline\server\Whiteboard.LicenseServer
dotnet publish -c Release -o publish
```

Отправить папку `publish` на сервер в `/var/www/schoolpiboardoff/api/`
(любым способом: WinSCP, `scp`, `rsync`).

Дальше — systemd и nginx по инструкции в `docs/deploy.md`.
Схему базы сервис создаёт сам при первом запуске.

### 3. Страница покупки — на ваш сайт

`offline\web\index.html` — готовый файл. Собирать нечего: откройте, замените
всё, что помечено словом `ЗАГЛУШКА` (адрес сервера лицензий в форме, ссылку
на установщик, реквизиты), и вставьте в свой сайт как обычную страницу.

## Онлайн-доска (`online/`)

### 1. Сервер — на сервер

```
cd SchoolPiBoard\online\server\SchoolPiBoard.Online
dotnet publish -c Release -o publish
```

Папку `publish` — на сервер в `/var/www/schoolpiboardon/api/`.

### 2. Сайт — на сервер

```
cd SchoolPiBoard\online\webapp
npm ci
set VITE_API_URL=/api        &:: в PowerShell: $env:VITE_API_URL="/api"
npm run build
```

Содержимое папки `dist` — на сервер в `/var/www/schoolpiboardon/web/`.

`VITE_API_URL=/api` обязательно: сайт и сервер живут на одном домене,
nginx направляет всё, что начинается с `/api`, в приложение. Забыть это —
самая частая причина «сайт открылся, но ничего не работает».

### 3. Запуск на сервере

Всё, что нужно — в `docs/deploy.md`: unit-файлы systemd (там же перечислены
все переменные с секретами), конфиг nginx, порядок первого запуска.
Схему базы сервис создаёт сам.

---

## Что на сервере лежит в итоге

```
/var/www/schoolpiboardoff/
  api/                      результат dotnet publish сервера лицензий

/var/www/schoolpiboardon/
  api/                      результат dotnet publish сервера онлайн-доски
  web/                      содержимое dist веб-приложения
```

Исходников на сервере нет и не нужно. Секреты — не в файлах репозитория,
а в переменных окружения systemd (или в отдельном файле с правами `600`).

## Разработка на своём ПК

Проверить онлайн-доску целиком, ничего не выкладывая:

```
:: первое окно — сервер
cd online\server\SchoolPiBoard.Online
dotnet run

:: второе окно — сайт
cd online\webapp
npm install
npm run dev
```

Сайт откроется на `http://localhost:5173`, сервер — на `http://localhost:5000`.

В режиме разработки не нужны ни SMTP, ни Redis, ни капча: письма пишутся
в консоль сервера (**ссылку подтверждения регистрации ищите там**), список
присутствующих держится в памяти, капча не проверяется. Нужен только
PostgreSQL с базой `schoolpiboard_online` — строка подключения лежит
в `appsettings.Development.json`.

## Как выкладывать обновления

**Десктопное приложение.** Поднять `<Version>` в `offline\Whiteboard.csproj`
и `AppVersion` в `installer\Whiteboard.iss`, собрать установщик, заменить
файл на сайте. У пользователей ничего не сломается: установщик ставится
поверх, доски и лицензия лежат отдельно и не трогаются.

**Любой из серверов.** Собрать заново, скопировать папку `publish`,
перезапустить службу:

```
sudo systemctl restart schoolpiboardon
```

Новые скрипты схемы применяются при старте сами.

**Сайт.** Собрать заново и заменить содержимое `web/`. Перезапускать
ничего не нужно — nginx отдаёт файлы как есть.
