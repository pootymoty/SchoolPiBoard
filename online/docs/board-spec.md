# Онлайн-доска: что готово и что осталось сделать

Задание для того, кто продолжает работу над `online/`. Продукт —
сайт school-pi-board.online: совместная доска в браузере по подписке.

## Главное правило

**С десктопной доской не связывать ничем.** Это отдельный продукт: свой
домен, свой сервис, своя база `schoolpiboard_online`, свои учётные записи,
свой магазин Робокассы. Общего кода нет намеренно, и появляться он не должен.
Покупатель бессрочного ключа и подписчик сайта — разные люди с разными
сценариями.

Практически это значит: не переиспользовать сервер лицензий, не ходить
в его базу, не делать общий вход, не заводить один магазин Робокассы
на два продукта. У магазина один ResultURL — общий магазин связал бы
два сервиса и общей нумерацией счетов.

## Раскладка

| | |
|---|---|
| Домен | school-pi-board.online |
| Папка на сервере | `/var/www/schoolpiboardon` |
| Бэкенд | `online/server/SchoolPiBoard.Online` — ASP.NET Core 8, minimal API, SignalR |
| Фронтенд | `online/webapp` — React 18 + TypeScript + Vite |
| База | PostgreSQL, `schoolpiboard_online`, схема применяется при старте из `sql/*.sql` |
| Redis | backplane SignalR и список присутствующих; в Production обязателен |
| Уведомление об оплате | `/billing/robokassa/result` |

Развёртывание — `deploy.md` и `runbook.md` в этой же папке.

## Что уже работает

**Учётные записи.** Регистрация с подтверждением по почте (заявка живёт
час), вход по JWT, профиль, смена пароля, удаление аккаунта с подтверждением
по почте. Пароли — PBKDF2-HMAC-SHA256, 210 000 итераций.

**Доски и участники.** Создание, список с пагинацией, архив, фон доски.
Три роли: `owner`, `editor`, `viewer`. Приглашения двумя способами —
персональное по адресу почты и ссылка. Ссылка живёт 7 дней
(`Invites__LinkLifetimeDays`), право на правки у приглашённого — 30 дней
(`Invites__MemberEditorDays`), после чего он становится наблюдателем,
и вернуть ему роль может только владелец. Логика в
`BoardMember.EffectiveRole`.

**Подписка.** Пробный период 7 дней, четыре плана: 30 дней — 499 ₽,
90 — 1449 ₽, 180 — 2799 ₽, 365 — 5399 ₽. Оплата через Робокассу,
подпись MD5, проверка уведомления по Password2, ответ `OK{InvId}`.
Отмена подписки сохраняет доступ до конца оплаченного срока.

**Реальное время.** SignalR-хаб на `/hub/board`. Методы: `JoinBoard`,
`LeaveBoard`, `CursorMove`. События клиенту: `UserJoined`, `UserLeft`,
`CursorMoved`. Присутствие хранится в Redis, поэтому работает и при
нескольких процессах.

**Сайт.** Лендинг с книжными полками, вход и регистрация, список досок,
страница доски, подписка, профиль, вход по приглашению, правовые страницы.

## Чего нет — это и есть работа

### 1. Холста нет вообще

`online/webapp/src/pages/BoardPage.tsx` показывает заглушку: «Здесь
появится холст». Всё остальное вокруг холста готово — роль, список
участников, статус соединения, курсоры.

**На сервере нет хранения содержимого доски.** В модели `Board` есть
только имя, фон и участники; таблицы объектов доски не существует.
Её нужно спроектировать и добавить в `sql/`.

### 2. Автопродление подписки не реализовано

Эндпоинт `/billing/auto-renew` переключает флаг, но повторных списаний
нет. Что для этого нужно от Робокассы — в `robokassa-recurring.md`.

### 3. Капча выключена

`Captcha__Provider=disabled`. Код проверки написан и ждёт ключей
Yandex SmartCaptcha. Включается двумя значениями, трогать не нужно.

### 4. Правовые тексты — заглушки

`online/webapp/src/pages/LegalPage.tsx` и реквизиты в подвале.

## Что сделать с холстом

**Рисование.** Перо, ластик, фигуры, текст, изображения, выделение
и перемещение. Ориентир — десктопная доска, но код у неё свой, брать
оттуда нечего.

**Роли.** `viewer` не рисует: инструменты скрыты, а сервер отклоняет
операции от него — проверять надо на сервере, а не только прятать кнопки
в интерфейсе. Роль приходит в `BoardJoinedDto` полями `canEdit`
и `canManage`, но доверять клиенту нельзя.

**Одновременная работа.** До 20 участников на доске. Операции идут через
существующий хаб: добавить методы вроде `ApplyOperation` и событие
`OperationApplied`, рассылку — в группу доски `board:{id}`.

**Сохранение.** Содержимое должно переживать перезагрузку страницы и
перезапуск сервиса: новый участник, войдя, получает актуальное состояние.
Хранить в PostgreSQL. Схему добавлять отдельным идемпотентным скриптом
в `sql/` — они применяются при старте.

**Разрешение конфликтов.** Двое рисуют одновременно — это норма, а не
ошибка. Решение выбрать и описать в комментарии: порядок операций
на сервере, версии объектов или что-то ещё. Главное, чтобы у всех
в итоге получалась одна и та же доска.

**Отмена.** Ctrl+Z должен отменять свои действия, а не чужие.

## Технические ограничения

- Библиотеку для холста выбрать самим. В `package.json` её пока нет:
  `@microsoft/signalr`, `react`, `react-dom`, `react-router-dom` — всё.
  Изначально предполагался `react-konva`, но это не обязательство.
- Сборка фронтенда — на ПК или на сервере, `npm run build`. Сервер
  слабый, но с этим справляется.
- `npm run build` включает `tsc --noEmit`: типы должны сходиться.

## Чего не делать

- не трогать `offline/` — это другой продукт;
- не заводить второй источник номеров счетов: их выдаёт база
  сервера онлайн-доски, и они же приходят обратно от Робокассы;
- не проверять роль только на клиенте;
- не выносить пароли Робокассы и `AUTH_TOKEN_SECRET` в код и в репозиторий —
  они живут в переменных окружения на сервере;
- не делать общий вход с десктопной доской ни в каком виде.
